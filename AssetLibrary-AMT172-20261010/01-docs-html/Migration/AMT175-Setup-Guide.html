2 · Startup After Reboot

Use when SQL Server, IIS, and AMT175 are already installed — Keycloak just needs to be brought back up.

$env:JAVA_HOME = "C:\Program Files\Microsoft\jdk-21.0.11.10-hotspot"
$env:Path = "$env:JAVA_HOME\bin;$env:Path"
Set-Location "C:\Keycloak\keycloak-26.2.5\bin"
Start-Process "cmd.exe" -ArgumentList "/c kc.bat start-dev --http-port 8080 > C:\Keycloak\keycloak.log 2>&1" -WindowStyle Minimized
Write-Host "Waiting for Keycloak on port 8080..."
for ($i = 1; $i -le 24; $i++) {
    Start-Sleep -Seconds 5
    $up = (Test-NetConnection localhost -Port 8080 -WarningAction SilentlyContinue).TcpTestSucceeded
    if ($up) { Write-Host "Keycloak UP at $($i*5)s"; break }
    Write-Host "  $($i*5)s..."
}

Then open AMT175 Control Center and sign in with your Keycloak credentials (realm amt175).

Optional preflight check: .\scripts\preflight.ps1 (verifies ports, AMTSYSTEM, SDK version, Keycloak reachability).

2a · Ensure IIS is up (Control Center is IIS-hosted, not a standalone process)

Run in an elevated PowerShell after reboot — Control Center runs under IIS via the ASP.NET Core Module, so IIS/W3SVC must be running and the AMT175 app pool started before the CC URL will respond.

# Ensure IIS services are running
Start-Service W3SVC, WAS -ErrorAction SilentlyContinue
Get-Service W3SVC, WAS | Select-Object Name, Status

# Check AMT175 app pool / site state
& "$env:windir\System32\inetsrv\appcmd.exe" list apppool
& "$env:windir\System32\inetsrv\appcmd.exe" list site

# Start AMT175's app pool if stopped (replace <PoolName> with actual name from list above)
& "$env:windir\System32\inetsrv\appcmd.exe" start apppool /apppool.name:"<PoolName>"

Symptom if skipped: CC URL returns HTTP 500 — This page isn't working (nothing listening on 5175/7175).

2b · If IIS Manager (inetmgr) opens as a blank window

The GUI console can break independently of the actual IIS service — use the appcmd commands above instead of the GUI. To repair the console itself, try in order:

  1. Close inetmgr, delete %LOCALAPPDATA%\Microsoft\Inetmgr\config, reopen
  2. Control Panel → Programs → Turn Windows features on/off → uncheck IIS Management Console → Apply → re-check → Apply
  3. Validate applicationHost.config is not corrupted: 
    [xml](Get-Content "$env:windir\System32\inetsrv\config\applicationHost.config") | Out-Null
    If this throws, the config file is broken — check Event Viewer → Application log for InetMgr/IIS errors.
