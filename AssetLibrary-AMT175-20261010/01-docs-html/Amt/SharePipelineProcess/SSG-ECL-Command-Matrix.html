1 · Overview

This page is a cross-reference matrix: rows = ECL or SSG directives, columns = the 16 ASSURFED utility programs. Cells are populated each time a program is processed through the trial pipeline. Each confirmed cell links to a transformation pattern card in §4 showing exactly what the PowerShell pre-processor does with the construct, and what C# AMT runtime result it produces.

Scope: This matrix covers constructs found within the SSG source .TXT files (what the pre-processor handles) and in the production ECL runstreams (from RunsPrd\). Production ECL rows are populated using find-ssg-ecl.ps1 as each program is analysed. 4 · Transformation Patterns

Compact summary cards for each directive that appears in the matrices above. Each card shows the PowerShell pre-processor action and the post-migration C# runtime result. Not the PRD OS2200 ECL execution — these are the migration-side transformations. For full deep-dive pattern cards (SSG source → C# code), see SSG/COBOL Reference §7.

P1 — @SSG,IA / @XQT .progname / @USE / @FREE

Standard ECL invocation pattern — replaces the full OS2200 compile → assign → execute → free lifecycle

▶ PowerShell (pre-processor + harness)

@SSG,IA → replaced by the full pipeline:
Convert-SsgToLion.ps1 (Remove-SsgDirectives + CobolConverterConsole) produces a validated .LionSource candidate.

@USE logicalname,physicalfile → assign.json fileAssignments map ("FILEIN-1": "input.dat") + Copy-Item into the per-job work dir in Run-EclProof.ps1.

@XQT .MONTANT → Run-EclProof.ps1 Xqt block invokes tools/refimpl/<key>.ps1 (Tier-1 oracle).

@FREE → harness wipes and recreates the per-job work dir after each run (idempotent, no residue).

▶ C# post-migration runtime (AMT .NET)

@SSG,IA → The compiled program is the generated C# class imported from .LionSource into AMT Dev Studio.

@USE / file assignment → m_FileInName / m_FileOutName fields in Montant.Files.cs, consumed by SetOptions(m_FileInName, ...) (deep-dive: T4 pattern).

@XQT .progname → Tier-2 (future): BatchController.Execute(programId) via AmtPsEclLib; Tier-1: direct refimpl call.

@FREE → AmtFileId close / resource cleanup at end of run.

See SSG-ECL Reference §2 — Execution Model for the full Tier 1/2/3 breakdown.

Applies to: MON LEC TRI ARB1 + all remaining SSG-template programs

P2 — *DEFINE name / *SET varname TO expr / *PROCESS name args / *END

Named macro definition and invocation — e.g. FILUN / FILDEU helpers in MONTANT_SIGNE

▶ PowerShell (Remove-SsgDirectives.ps1)

The entire *DEFINE…*END block is stripped from the output. When a *PROCESS macroname arg1 arg2 line is encountered, the pre-processor evaluates the *SET arithmetic expression using the supplied arguments and stores the result. Any subsequent [*varname] token in the COBOL body is then substituted with the computed integer literal.

example (MONTANT_SIGNE) 
*DEFINE FILUN
*SET FILLUN TO [#1]-1   ← stripped from output
*END
*PROCESS FILUN [MONTANT,I,1,1]   ← evaluates FILLUN = offset-1
  03 FILLER PIC X([*FILLUN]).     ← [*FILLUN] → literal e.g. 1

▶ C# post-migration runtime (AMT .NET)

The SSG macro becomes a static helper method in LocalDefinitions.cs. The method implements the same arithmetic as the *SET expression:

csharp (generated — MONTANT_SIGNE) 
// SSG *DEFINE FILUN → *SET FILLUN TO [#1]-1
private static int FilUn(int offset) => offset - 1;

// SSG *DEFINE FILDEU → *SET FILLDEU TO [#1]-[#2]-[#3]+1
private static int FilDeu(int recSize, int offset, int width)
    => recSize - offset - width + 1;

Full deep-dive: SSG/COBOL Reference §7 — T2 pattern

Confirmed in: MON CMP2 CFH ASEP AFMT COMPARE2 uses *DEFINE for PAS/FILUN/FILDEUX macros (trial-10). CFH-COPY uses *DEFINE FILER + *SET FILLCTR (trial-11). ARCHISEPARE/ARCHIFORMAT use standalone *SET (no *DEFINE block): pure expression evaluation, e.g. *SET [*c] = [*b]+[*a]-[key,1,1,3]+1 — including N-operand chains fixed at trial-13 (trial-12/13).

P3 — *INCREMENT I FROM n BY m TO [param] … *LOOP

Loop-generate repeated COBOL blocks — N separate REDEFINES structures from one template

▶ PowerShell (Remove-SsgDirectives.ps1)

The pre-processor expands the loop at compile time: for each value of I from n to the resolved upper bound, it emits one copy of the loop body with [*I] substituted by the current counter value. The *INCREMENT and *LOOP lines themselves are stripped.

ssg input → cobol output (n=1, bound=2) 
*INCREMENT I FROM 1 BY 1 TO [MONTANT]
  01 WS-IN[*I] REDEFINES WS-IN.
*LOOP
↓ expands to:
  01 WS-IN1 REDEFINES WS-IN.
  01 WS-IN2 REDEFINES WS-IN.

▶ C# post-migration runtime (AMT .NET)

The N static REDEFINES overlays become a dynamic foreach loop in the constructor of LocalDefinitions.cs, creating AmtStructure + AmtVarNumericOS2200 instances at runtime:

csharp (generated) 
foreach (var (offset, width) in fields) {
  var wsIn = new AmtStructure();
  wsIn.Redefines(m_Ws_In);
  wsIn.AddAlphaFiller(FilUn(offset));
  m_InFields.Add(new AmtVarNumericOS2200(width, true, wsIn));
  wsIn.AddAlphaFiller(FilDeu(recSizeIn, offset, width));
}

Full deep-dive: SSG/COBOL Reference §7 — T1 pattern

Confirmed in: MON ECLAT LMND ECLAT uses named loop variables ([*a], [*b], …) not [*I]; loop body manually expanded for key=1 (automated expansion deferred). Others: pending analysis.

P4 — *IF condition / *ELSE / *ENDIF

Conditional code generation — multi-variant programs (LECTIS, TRI_ASCII)

▶ PowerShell (Remove-SsgDirectives.ps1)

Resolve-SsgCondition evaluates each *IF branch using the -ConditionValues hashtable supplied via programs.manifest.json. The selected branch body is kept; all other branches are stripped. The *IF / *ELSE / *ENDIF lines themselves are removed. String comparisons (*IF [PARAM] = WORD) are resolved against the matching -ParamOverrides value.

Without correct conditionValues, multiple branches produce duplicate DATA DIVISION entries that the AMT converter rejects with a “duplicate field definition” error.

▶ C# post-migration runtime (AMT .NET)

There is no runtime conditional: the branch was already resolved at pre-process time. The generated C# contains only the selected code path. This is intentional — SSG conditionals are compile-time variant selection, not runtime branching logic.

Example: LECTIS with ASCII=1, LKEY=2 → the ASCII-mode, two-key variant is the only code generated. The IS-file API (OpenFile / LocateRecordIndexedFile / ReadRandomAccessFileNextRecord) appears because the UN=1 (unordered) branch was selected.

See SSG-ECL Reference §5 — *IF/*DEFINE Handling

Confirmed in: LEC TRI SCAN ECLAT CMP2 CFH ASEP LMND UNL ECLAT closes blocks with *ENDIF (not *END); matched by ^\*END(?:IF)?\b. COMPARE2 uses bare conditions (*IF [PARAM]) and numeric OR (trial-10). CFH-COPY introduces string-string OR: *IF [OUTPUT,1,1,1] = CARDPUNCH OR [OUTPUT,1,1,1] = PRINTER (trial-11). ARCHISEPARE adds *ELSEIF + branchTaken tracking (trial-12). MON/AFMT confirmed absent; ARB1 no SSG directives.

P5 — Parameter Token Forms: [PARAM,r,c,f] / [PARAM,r,A,f] / [PARAM,r,COL,f] / [*varname] / [*I]

Inline ECL/SSG parameter substitution — the pre-processor's primary token replacement work

▶ PowerShell (Remove-SsgDirectives.ps1)

All token forms are substituted with literal values from the paramOverrides hashtable in programs.manifest.json. Unmatched tokens collapse to 1 (catch-all).

Token formExampleValue from

[P,r,COL,f][KEYS,1,COL,2]paramOverrides["[KEYS,1,COL,2]"]

P6 — #ucob,is .name,.name / @UCOB,I

Inline COBOL compile directives — programs using #ucob,is / @UCOB,I compile inline rather than via the SSG template (@SSG,IA) path

▶ PowerShell (Remove-SsgDirectives.ps1 — confirmed trial-07)

#ucob,is .architab1,.architab1 is an ECL-embedded COBOL compile header: it tells the OS2200 executor to compile the following COBOL inline (not via @SSG,IA). This means ARCHITAB1 is plain COBOL, not an SSG macro template.

Confirmed at trial-07: Remove-SsgDirectives.ps1 strips the #ucob,is header line via the ^#ucob\b rule. The source has exactly one such line (the opening header); no other UCOb-style directives appear. Result: 120 lines in → 119 lines out, 1 control line stripped, 8 COBOL lines substituted ([fname,1,1,1], [tname,1,1,1/2] × 2, [key,1,1,1/2/3] × 2, each annotated *> SSG-STUB).

Candidate: EclCobolPipeline/candidates/trial-07-architab1/ARCHITAB1.TXT

▶ C# post-migration runtime (AMT .NET)

Because ARCHITAB1 is plain COBOL (not SSG macro), the generated C# is expected to be simpler than MONTANT/LECTIS/TRI_ASCII — no *INCREMENT loop, no *DEFINE helpers, no *IF variants.

The ECL stub rule applies from trial-07: any [fname,1,1,1] token substituted should be renamed to an ECL_-prefixed identifier with a *> SSG-STUB annotation comment.

See SSG-ECL Reference §4 — Stub naming rule (from Trial 07)

Confirmed in: ARB1 ASEP AFMT ARB1=#ucob,is (trial-07); ASEP=#ucob,is (trial-12); AFMT=#ucob,is (trial-13). MON / LEC / TRI confirmed absent.
