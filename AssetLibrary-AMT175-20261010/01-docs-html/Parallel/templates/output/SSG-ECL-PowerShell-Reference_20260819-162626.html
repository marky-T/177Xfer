SSG-ECL / PowerShell Pre-Processor Pipeline

Reference for the script pipeline that turns raw SSG/ECL source into convertible COBOL

Last updated: 2026-06-26  |  AMT 172 (8.0.26125.0 RC1)  |  Federale migration — SSG/ECL → COBOL → Lion → C#  |  Companion to SSG/COBOL Reference

1 · Overview

The Federale SSG utility programs are not plain COBOL. Each ASSURFED_* source file is a macro-COBOL hybrid: COBOL divisions interleaved with SSG macro directives (*DEFINE, *IF, *SET, *END) and ECL job parameters ([INPUT,1,1,1] style tokens). The AMT CobolConverter cannot parse those directives directly, so a PowerShell pre-processor pipeline resolves them into clean COBOL before conversion.

This page documents the pre-conversion half of Phase 12. The downstream COBOL → Lion → C# detail, worked program examples, and transformation pattern cards live on the SSG/COBOL Reference ↗.

Where it sits in the migration

pipeline 
Raw SSG/ECL source (ASSURFED_*.TXT)
  Remove-SsgDirectives.ps1   # strip *IF/*DEFINE, substitute [param] tokens
    clean COBOL candidate (<PROGRAM-ID>.TXT)

        .LionSource  →  [Phase 13] LionDevGenNet  →  C# assembly

Authoritative rule

Always use the established script pipeline to produce candidate files. Hand-authoring a candidate is a fallback only when the source is already plain COBOL with no SSG directives. See .github/instructions/amt-cobol-migration.instructions.md.

2 · Execution Model — Execute vs. Orchestrate

Running a converted SSG-COBOL utility (e.g. MONTANT) involves two distinct layers. Keeping them apart explains why the proof harness needs no PowerShell while production does.

LayerWhat it doesNeeded to run
MONTANT's logic?
AMT .NET runtime
(the C# framework)		 Actually executes the converted program — the file READ/WRITE, the COMPUTE, the sort API, indexed-file I/O Yes — this is what runs the code
AMT PowerShell ECL framework
(AmtPsEclLib)		 Job control migrated from the ECL runstream: sets up file assignments (FILEIN-1 → a path), then Xqts the program via the BatchController No — it kicks off and wires the program; it does not run the COBOL logic
The PowerShell library is the job-control / file-assignment / invocation layer (Stream B). It never performs the program's computation — Xqt just inserts a job request and the BatchController runs the converted program (which is C# on the AMT .NET runtime).

Three proof tiers

Tier 2 — AMT .NET runtime done Runs the actual converted C# under the AMT .NET runtime — the deployed program DLL is Xqted by the Control Center BatchController as a real batch job (app AFBUS_2200COBOL). Proven end-to-end (2026-07-18): MONTANT ran Queued → Running → Completed and its output was byte-identical to the Tier-1 golden. Inputs/outputs resolve as %SYSROOT%\Files\Extracts\<designator>.DAT — stage each fixture input there and collect the output from the same place. See §6b Control Center Runbook. AMT .NET runtime + Control Center (no PowerShell ECL needed)

Design bridge: the Tier 1 mock-shell is modelled on the AMT PowerShell ECL skeleton (Import-Module AmtPsEclLib → Set-Jobname → file assignments → Xqt-style call), so the same harness invokes the oracle now, the converted C# later, and graduates into the real Stream B script eventually.

3 · Pre-Processor Pipeline

Two scripts make up the pipeline. Convert-SsgToLion.ps1 is the orchestrator you normally run; it calls Remove-SsgDirectives.ps1 first, then invokes the converter.

Remove-SsgDirectives.ps1

Resolves the SSG macro layer into plain COBOL:

  • Strips *IF / *ELSEIF / *ELSE / *END / *ENDIF directive lines (*ENDIF is used by ECLAT in place of *END; matched by ^\*END(?:IF)?\b). *ELSEIF is handled via a branchTaken flag on the condition stack — once any branch fires, all subsequent *ELSEIF/*ELSE arms are suppressed (trial-12 ARCHISEPARE). Emits only the branch selected by -ConditionValues.
  • Unrolls *INCREMENT…*LOOP blocks: expands each iteration substituting [*I] and indexed [PARAM,r,n,f] tokens, producing one copy of the loop body per iteration count (trial-11+; confirmed for FILE-CONTROL/FD/OPEN+CLOSE loops in trial-14 LOADIS_MULT-NODUP).
  • Evaluates *SET [*varname] = <expr> assignments and substitutes [*varname] references throughout the emitted output. Supports N-operand arithmetic chains (+ - * /) via Eval-SsgSetExpr (trial-12 ARCHISEPARE; N-operand form trial-13 ARCHIFORMAT).
  • Suppresses entire *DEFINE macro bodies (tracks $inDefineBlock + $defineIfDepth, including nested *IF content) so FILLER lines inside a *DEFINE body never leak in front of IDENTIFICATION DIVISION.
  • Strips extended SSG control lines: *BRKPT, *SORT, *EXIT, *ITERATE, *ABORT, *DISPLAY, *MESSAGE, *. (SSG comment lines starting with *.).
  • Strips ECL job-control directives embedded in SSG source: #ASG, #USE, #LINK, #FREE, #DELETE, #CAT, #XQT. Non-directive content lines inside a #LINK…#FREE linker block (e.g. INCLUDE, OUTPUT, RESOLVE) are suppressed via the $inLinkBlock state variable.
  • Strips COBOL-source ECL lines: #ACOB (general COBOL generation control; trial-03+) and #ucob,is (plain-COBOL path marker for ARCHITAB1-style programs; trial-07+).
  • Substitutes inline [param] tokens with the values from -ParamOverrides (catch-all unmatched tokens collapse to 1).
  • -AnnotateStubs switch (trial-07+): appends   *> SSG-STUB [original-token] as a COBOL inline comment on every line where a token was substituted, preserving traceability back to the SSG source parameter.
  • Resolve-SsgCondition evaluates *IF [PARAM] = WORD string comparisons using the override value (needed for TRI_ASCII’s *IF [INPUT,1,A,1] = CARDREADER style conditions).
Output is a single clean COBOL file named after the PROGRAM-ID — see §7, Bug 14.

Convert-SsgToLion.ps1

Orchestrates the full step: Remove-SsgDirectives → CobolConverterConsole.exe. Driven by a .settings JSON plus per-program override hashtables.

  -SettingsFile "C:\Amt\Migration\CobolConvert\settings\trial-05-lectis.settings" `
  -RawSourceDir "C:\Amt\MainframeSource\Codedrop 2025\SSG Prd\SSG Creating COBOL" `

      '[INPUT,1,1,1]' = 'FICHIN-1'

  -ConditionValues @{
      'ASCII' = 1;  'LKEY' = 2;  'KEYS' = 0;  'COND,1' = 0

4 · ECL Parameter Substitution

ECL job parameters appear in the source as bracketed tokens. The pre-processor replaces each with a concrete value supplied through -ParamOverrides; any token left unmatched is collapsed to 1 by a generic catch-all.

Token anatomy

ecl token 
[INPUT,1,1,1]   ← stream, position, occurrence, sub-field
   |     | | |
   |     | | ↳ field index (1=name, 2=record size, 3=block size)
   |     | ↳ occurrence
   |     ↳ position
   ↳ ECL stream name (INPUT / OUTPUT / LKEY / MONTANT / ...)

Common ECL fields

The third field (occurrence) may be A (all/any — sort/array stream contexts, seen in TRI_ASCII), and the sub-field index may be a named word rather than a number (e.g. COL for column width in [KEYS,n,COL,2]).

TokenMeaningSeen inC# transform tier
[INPUT,1,1,1]Input file nameMONTANT (default), LECTIS, COMPARE2 (IN1)T4 (file name)
[INPUT,1,1,2]Input record size or second file name (see note ↓)MONTANT/LECTIS (record size); COMPARE2 (IN2 file name)T3 / T4
[INPUT,1,1,3]Input block size or record size (see note ↓)LECTIS (block size); COMPARE2 (record size)T5 / T3
[INPUT,1,1,4]Block count (COMPARE2 multi-file — field shifts)COMPARE2T5 (stored only)
[INPUT,1,A,1]Input file name — A-variant (sort stream)TRI_ASCIIT4 (file name)
[INPUT,1,A,2]Input record size — A-variantTRI_ASCIIT3 (record size)
[OUTPUT,1,1,1]Output file name / PROGRAM-ID seedTRI_ASCIIT4
[LKEY,1,1,2]Key 1 widthLECTIST_KEY
[LKEY,2,1,2]Key 2 widthLECTIST_KEY
[KEYS,1,COL,2]Sort key column width (COL sub-field)TRI_ASCIIT_KEY
Multi-file field-shift note (COMPARE2_ASCII, trial-10): When an SSG template declares two input files under the same INPUT stream, the sub-field index shifts by one: fields 1 and 2 carry the two file names, pushing record size to field 3 and block count to field 4. Single-file programs (MONTANT, LECTIS) use fields 1/2/3 for name/record-size/block-size respectively. The field semantics are template-specific — always verify against the source *DEFINE bodies and -ParamOverrides in the manifest.

Stub naming (traceability)

Current state (Trials 03–06 — MONTANT, LECTIS, TRI_ASCII): The pre-processor performs direct inline substitution only — [INPUT,1,1,2] becomes 80 literally. No ECL_ stub identifiers are created and no *> annotation comments are added. Confirmed by inspection of all three candidates and their .LionSource outputs (zero ECL_ / *> lines found).

Rule — applied from Trial 07 (ARCHITAB1) onwards: After each ECL token is substituted, the resulting COBOL stub must be renamed to an ECL_-prefixed identifier and a preceding *> SSG-STUB comment must carry the verbatim original token. This makes every substituted value searchable in AMT from ECL source param → annotated COBOL stub → .LionSource → generated C# field:

cobol (target format — to apply from Trial 07) 
*> SSG-STUB ECL_INPUT_RECSIZE = [INPUT,1,1,2]   (record size)
01  ECL-IN  PIC X(80).        *> was PIC X([INPUT,1,1,2])
Stub names & their token / tier / helper mapping are tabulated on the SSG/COBOL Reference §7 pattern cards ↗. Survival of *> comments into emitted C#: confirmed the current pre-processor does not produce them (Trials 03–06 direct substitution). Whether the AMT converter preserves them once added will be verified at Trial 07 (ARCHITAB1).

Marker & lineage convention

Two distinct markers keep this work traceable — one reaches the generated objects you run in AMT, the other does not. Code lineage markers are not yet applied (Trials 03–06); the rule above mandates them from Trial 07 (ARCHITAB1) onwards.

MarkerFormWhereReaches AMT / C#?Status
Code lineage ECL_ / SSG_ prefix on stub identifiers annotated COBOL stubs → .LionSource → generated .cs Yes (when applied) From Trial 07
Documentation ECLREF HTML-comment pairs; eclref- on new ids/classes inserted fragments in the guide / this reference set No Active
Prefix, not suffix, for the code-lineage marker: the identifier survives even if the generator strips *> comments, sorts/groups together in AMT’s object explorer and side-by-side diffs, and avoids hyphen→underscore mangling. A single search for ECL_ then traces a value from the ECL job param → annotated COBOL stub → .LionSource → the C# field under review in AMT.

5 · SSG *IF / *DEFINE Handling

SSG source carries multiple conditional variants of the same program. Emitting more than one branch produces duplicate field definitions that the converter rejects, so -ConditionValues selects exactly one branch per condition.

-ConditionValues

powershell 
-ConditionValues @{
    'ASCII'  = 1     # take the *IF ASCII branch
    'LKEY'   = 2     # two key fields
    'KEYS'   = 0
    'NOLIST' = 0
    'COND,1' = 0
}
  • A numeric value selects which *IF <COND> arm is emitted.
  • String comparisons (*IF [PARAM] = WORD) resolve against the matching -ParamOverrides value via Resolve-SsgCondition.
  • Required for multi-variant programs (e.g. LECTIS) to avoid duplicate WS items.

*DEFINE block suppression

A *DEFINE body can contain FILLER and nested *IF lines. If not suppressed, those lines appear before IDENTIFICATION DIVISION and the converter fails. The pre-processor tracks $inDefineBlock + $defineIfDepth to strip the entire body.

Verifying the candidate

  1. Inspect BatchDir\<PROGRAM-ID>.TXT for residual [token] patterns the catch-all replaced with 1; tighten -ParamOverrides if the stubs are not meaningful.
  2. If the converter log reports unknown bare-word tokens, add them to ssg-stub.macros.xml and update its inventory comment.

6b · Control Center Runbook — Tier 2 live batch execution

Operational runbook for executing any converted AFBUS_2200COBOL utility as a real Control Center batch job (the Tier 2 path in §2). It reuses the same fixtures and expected.dat goldens as the Tier 1 harness — only the executor changes: the AMT .NET runtime runs the deployed program DLL, Xqted by the BatchController, instead of the PowerShell oracle. Worked examples: MONTANT & CFH_COPY (full passes, diff=0).

File-resolution model (confirmed 2026-07-18) — working-dir staging works. Both input and output DISC files resolve to %SYSROOT%\Files\Extracts\<DISC-designator>.DAT (= C:\Amt\Working\Lion\Files\Extracts\<designator>.DAT). The designator is the AmtFileId SetOptions(...) name in the generated <Program>.Files.cs (MONTANT: FILEIN→ECL-TAPEIN, FILEOUT→ECL-TAPEOUT). Stage each fixture input as <inputDesignator>.DAT there; the run reads it and writes <outputDesignator>.DAT alongside — proven byte-identical to the golden for MONTANT.
Retraction: the earlier “report model cannot feed inputs” note (2026-07-17) was premature — ARCHIFORMAT/ARCHITAB1 produced 1.DAT because their deployed output designator was the catch-all 1 (build-param divergence) and their inputs were never staged, not because of a model limitation. No AMTSYSBATCHFILE/AmtPsEclLib assignment is required.

1 · Bring the stack up (once per boot)

Run C:\Amt\Migration\tools\Federale_CC_Startup.ps1 elevated — starts, in dependency order: Keycloak (:8080) → IIS CC site → AmtFileController → AmtBatchController → AmtApplicationServer. CC UI: http://localhost/Working/ControlCenter/.

4 · Feed a fixture & prove the output (working-dir staging)

Read the program’s real DISC designators from its generated <Program>.Files.cs (m_<File>.SetOptions("<designator>", …)) — these, not the candidate or assign.json keys, are what the runtime resolves. Then:

  1. Copy each fixture input to C:\Amt\Working\Lion\Files\Extracts\<inputDesignator>.DAT (uppercase name, .DAT extension). E.g. MONTANT: input.dat → Files\Extracts\ECL-TAPEIN.DAT.
  2. CC → Jobs → Start Job → the job → Start job; wait for Completed.
  3. Collect the output Files\Extracts\<outputDesignator>.DAT (MONTANT: ECL-TAPEOUT.DAT).
  4. Diff vs fixtures\<key>\expected.dat — mask run-date bytes for date-sensitive programs (ARCHITAB1: cols 38–45 of type-0/9).
MONTANT (2026-07-18): staged ECL-TAPEIN.DAT → run → ECL-TAPEOUT.DAT = 328 B, byte-identical to the golden (diff=0). No file assignments, no DB writes, no AmtPsEclLib (which is not installed here).

5 · Known gotchas

  • FileController won't start (“File service FileController not found”): AMTSYSFILECONTROLLER.SERVICENAME must be exactly FileController.
  • Report DLL path: DLLs must be in Binaries\Reports\ with a bare-filename FILE (else a doubled-path load error).
  • CC Server-Control Start/Stop buttons are broken (impersonation NRE) — use the startup script / elevated PowerShell.
  • OIDC login loop over plain HTTP on full re-login — reprieve: clear cookies; durable fix: serve CC over HTTPS.
  • Missing Binaries\Common\* subfolders halt batch execution: the BatchController StartAppAssemblyMonitor throws “directory …\Common\Libraries\ does not exist”. Create the full set of Common\* subfolders (mirroring an app like AFBUS: Dlls, Libraries, Insertables, Types, runtimes, the ApplicationServerAgent / RestApi / Soap / Web provider dirs, etc.) even if empty.
  • A crashed job can wedge the BatchController agent (agent keeps the output file locked; AMTSYSPROCESSJOB shows a stuck Running row). Recover by Restart-Service AmtBatchController (elevated) — the restart Kills the stuck job and clears the lock — then clear any stale queued AMTSYSPROCESSJOB rows (e.g. old %APPROOT%\Programs\ path entries that keep erroring).
  • Newly deployed report DLL won’t run until the BatchController is re-synced (auto-sync is off): Start Job silently no-ops (no process row/log). Fix: Restart-Service AmtBatchController (elevated) to rebuild the report pool from Binaries\Reports\.

7 · Troubleshooting

Bug 14 — candidate filename must match PROGRAM-ID

The candidate .TXT filename must equal the PROGRAM-ID in the COBOL source, not the SSG element name. SSG element LECTIS_MULT has PROGRAM-ID. LECTIS. → the candidate must be named LECTIS.TXT.

The generator indexes by PROGRAM-ID (CobolApp.Sources.Find(objNameWm)). A mismatch fails generation with Could not find source with name: <ID> even after the suffix is cleaned up.

Bug 15 — parse before generate

After importing the .LionSource into LionDev, always run Logic Status → Select All → F7 (Parse) before clicking Generate. Skipping this leaves REVGENSETDATA empty and generates empty C# files.

Residual [token] = 1

An unintended 1 in the candidate means a token was not in -ParamOverrides and hit the catch-all. Add the token with a meaningful value and re-run.

Bare-word macro tokens

Unknown tokens in the converter log are bare-word macros, not [param] tokens. Add entries to ssg-stub.macros.xml (and update its inventory comment — even when no new entries are needed).

Multiple *IF branches emitted (duplicate WS items)

Supply -ConditionValues for every condition so only one variant is emitted (see §4).
