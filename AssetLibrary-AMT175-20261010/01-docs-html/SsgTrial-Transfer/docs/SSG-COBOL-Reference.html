Federale SSG-COBOL Utility Programs

Reference & Investigation

Last updated: 2026-06-25  |  AMT 172 (8.0.26125.0 RC1)  |  Federale migration — AFBUS COBOL batch utilities

1. Overview

Federale (Belgian insurance company) uses a set of 16 SSG-COBOL utility programs as reusable batch file-transformation building blocks within its Unisys 2200 (OS 2200) mainframe estate. These programs are stored in the mainframe file library *UTILIT and correspond to the files in SSG Prd / SSG Creating COBOL from the 2025 code drop.

Unlike conventional compiled programs, these are SSG (Source Statement Generator) templates — parameterised COBOL source that is compiled inline at job runtime by the ECL job stream, not pre-compiled. Each invocation can produce a COBOL program with a different record layout by varying its macro parameters (record sizes, field positions, number of fields, etc.).

In the AMT 172 migration project, these programs are converted to C# using the COBOL Converter tool (Phase 12 → .LionSource) and then generated into a C# assembly by LionDevGenNet (Phase 13).

Source location (mainframe code drop):
C:\Amt\MainframeSource\Codedrop 2025\SSG Prd\SSG Creating COBOL\
16 files, all prefixed ASSURFED_UTILIT_, Windows-1252 encoded.
⚠ Encoding note: All ECL and SSG source files in this code drop are Windows-1252 encoded. VS Code's built-in search and grep tools return no results on these files. Always use PowerShell for any file reading or searching:

2. Unisys ECL — Key Directives

ECL (Executive Control Language) is the Unisys OS 2200 equivalent of JCL (IBM z/OS) or Windows batch scripts. A job stream is stored as a .TXT file in RunsPrd\. The directives relevant to SSG-COBOL program invocation are listed below.

DirectiveMeaning
@ASG,UP filename,options Assign (create) a new temporary file. UP = unscratched permanent. Options include F/granules/type/blocks.
@ASG,A filename Assign an existing catalogued file for use in this run.
@USE logicalname,physicalfile Bind a logical file name (the name used inside the program, e.g. INB) to a physical file path.
@DELETE,C filename Delete a file if it exists. ,C = conditional — no error if the file is absent.
@CAT,P filename,options Catalog (create) a permanent file. F/0/POS/nnnn = fixed organisation, 0 initial granules, POS type, nnnn block capacity.
@SSG,IA *qualifier.element/type Inline SSG assembly. Reads SSG macro parameters from the lines that follow, compiles the SSG-COBOL template on-the-fly, and makes the resulting program available for @XQT. The compiled object is stored in the TPF$ temporary namespace.
IA = Inline Assembly. *qualifier.element/type identifies the source in the mainframe library (e.g. *UTILIT.CFH-COPY/ASCII).
@XQT .progname
@XQT,WR .progname		 Execute a compiled program. The . prefix means "this run's TPF$ namespace" (the just-compiled object). WR = write-run (retain the run image).
@FREE filename Release a file assignment — detaches the logical name from the physical file.
@ADD qualifier*element Include another ECL stream inline, similar to #include. Commonly used for shared restart/recovery ECL (e.g. @ADD SYS$*RUNS.REPRISE).
@LAB label: MSG text Define a label with a console message. Other directives can branch to it on failure.
@EOF End-of-file marker / conditional branch: if the preceding command failed, execution skips to this point or to a named label.
@TIME Emit a timestamp entry to the job log.
@ERS qualifier$ Erase a scratch qualifier (all temporary files under that qualifier for this run).
File naming convention: Unisys files use a qualifier*element naming scheme. *UTILIT is a library qualifier (not a folder path). TPF$ is the scratch/temp qualifier used during inline compilation. The dot prefix in @XQT .MONTANT means "the object named MONTANT in this run's TPF$ scratch space."

3. SSG Macro Language

SSG (Source Statement Generator) is Unisys's pre-processor for COBOL on OS 2200. It expands parameterised templates into standard COBOL source before the COBOL compiler runs. Think of it as a macro assembler for COBOL — closer in spirit to C #define than to COBOL COPY statements, because it can conditionally generate or loop-generate entire DATA DIVISION entries.

3.1 Directives

DirectiveMeaning
*DEFINE name … *END Define a named macro. The body contains one or more *SET statements. Positional arguments are referenced as [#1], [#2], [#3].
*SET varname TO expression Within a *DEFINE block: compute a value and store it. Arithmetic on positional arguments and constants is supported.
*PROCESS macroname arg1 arg2 … Invoke a named macro with arguments. The result is stored as [*varname] (using the variable name from the macro's *SET statement).
*INCREMENT I FROM n BY m TO [param] Loop start: generate repeated COBOL code blocks. Loop variable I runs from n to [param] in steps of m. Use [*I] inside the block to embed the counter.
*LOOP End of *INCREMENT loop. Everything between *INCREMENT and *LOOP is repeated once per iteration.
*IF / *ELSE / *ENDIF Conditional code generation based on parameter values or other SSG variables.
#ACOB Assembler-COBOL bridge directive (OS 2200 specific). Marks an inline assembler section.
@UCOB,I target1,target2 ECL directive embedded in the SSG source: compile the following COBOL inline. I = immediate. Output objects are written to the TPF$ scratch space under the specified names.

3.2 Parameter Address Syntax

SSG macro parameters are supplied as a structured table on the control cards following @SSG,IA. Individual values within that table are addressed using four-part notation:

SSG parameter address syntax 
[PARAM, row, col, field]

  PARAM  — parameter group name (matches the control card keyword, e.g. INPUT, OUTPUT, MONTANT)
  row    — row number within that group (usually 1)
  col    — column/item number within the row (usually 1)
  field  — position of the sub-value within that item (1-based)

Examples from MONTANT_SIGNE:

  [INPUT,1,1,1]  → INPUT param, row 1, col 1, field 1  =  logical file name   (e.g. "INB")
  [INPUT,1,1,2]  → INPUT param, row 1, col 1, field 2  =  record size          (e.g. 80)
  [INPUT,1,1,3]  → INPUT param, row 1, col 1, field 3  =  blocking factor       (e.g. 1)
  [MONTANT]      → MONTANT param (scalar) =  number of amount fields  (e.g. 3)
  [MONTANT,I,1,1] → MONTANT param, row I (loop var), col 1, field 1  =  byte offset of field I
  [MONTANT,I,1,2] → MONTANT param, row I, col 1, field 2  =  digit width of field I

3.3 Computed References

When a *PROCESS macro is invoked, it stores its computed result in the named variable from the macro's *SET statement. That result is then referenced as [*varname] in the surrounding COBOL:

FILUN macro definition and usage (from MONTANT_SIGNE) 
*DEFINE FILUN                       ← define a macro named FILUN
*SET FILLUN  TO  [#1]-1             ← FILLUN = arg1 minus 1  (converts 1-based offset → filler byte count)
*END

Usage in DATA DIVISION:
*PROCESS FILUN [MONTANT,I,1,1]      ← invoke FILUN, passing field-start offset as argument 1
               03 FILLER  PIC X([*FILLUN]). ← reference the computed result

3.4 Loop Generation

The *INCREMENT … *LOOP construct generates repeated COBOL statements, substituting [*I] with the current loop counter. This is how a single SSG template produces N separate REDEFINES overlays — one per parameterised field — without any manual repetition:

Loop pattern — generates WS-IN1, WS-IN2, … WS-INn (n = [MONTANT]) 
*INCREMENT I FROM 1 BY 1 TO [MONTANT]        ← loop: I = 1, 2, … MONTANT
       01  WS-IN[*I] REDEFINES WS-IN.              ← generates: WS-IN1 REDEFINES WS-IN, WS-IN2 REDEFINES WS-IN, …
*PROCESS FILUN  [MONTANT,I,1,1]               ← compute filler = offset[I] − 1
               03 FILLER    PIC X([*FILLUN]).     ← skip bytes to reach field position
               03 MONTANT[*I]  PIC S9([MONTANT,I,1,2]). ← named signed numeric: MONTANT1, MONTANT2, …
*PROCESS FILDEU [INPUT,1,1,2] [MONTANT,I,1,1] [MONTANT,I,1,2]
               03 FILLER    PIC X([*FILLDEU]).    ← remaining bytes to end of record
*LOOP                                              ← end loop

4. ECL Invocation Pattern

The following is a real ECL extract from job stream ASSURFED_F999RUN_VIRM01_CO(P).TXT, showing a complete CFH-COPY invocation. This pattern — compile with parameters, then assign files, then execute — applies to all 16 SSG-COBOL utility programs.

ASSURFED_F999RUN_VIRM01_CO(P).TXT — CFH-COPY invocation (annotated) 
@ .  ───────────────────────────────────────────────────────────────────
@MSG  RECOPIER LES ENREGISTREMENTS  D'UN FICHIER ASCII.
@ .  ───────────────────────────────────────────────────────────────────

@SSG,IA  *UTILIT.CFH-COPY/ASCII           ← STEP 1: Compile SSG template from library *UTILIT
SGS                                                  SSG control card
ASCII                                                Parameter group name
INPUT      INB,500,10                               INPUT param: logname=INB, recsize=500, blocking=10
OUTPUT     INC,135,10                               OUTPUT param: logname=INC, recsize=135, blocking=10
FIELDIN    6,9 19,6 403,2 57,8 65,4 113,24 161,24 405,16 421,24 265,8
FIELDOUT   11,9 20,6 26,2 28,8 36,4 40,24 64,24 88,16 104,24 128,8
                                         ← blank line terminates the SSG parameter block
@ASG,A     I006VRM01ATT.                ← STEP 2: Assign physical input file
@USE       INB,I006VRM01ATT.                        Bind logical name INB → physical file I006VRM01ATT
@DELETE,C  I006VRM01ATC.                ← STEP 3: Clear output file (conditional)
@CAT,P     I006VRM01ATC,F/0/POS/4000               Create new permanent output file
@ASG,A     I006VRM01ATC.                            Assign it
@USE       INC,I006VRM01ATC                         Bind logical name INC → physical file I006VRM01ATC
@XQT,WR    .CFH-COPY                    ← STEP 4: Execute compiled program (. = TPF$ scope)
@FREE      I006VRM01ATC.                ← STEP 5: Release file assignments
@FREE      I006VRM01ATT.
@ERS       TPF$.                                    Erase all TPF$ temp files from this run
@TIME                                               Write timestamp to job log
@EOF                                                End of this job step

Key Observations

  • Compile first, assign files second. The @SSG,IA block with its parameter cards precedes the @ASG/@USE file assignments. The SSG compiler only needs the parameter values (record sizes, field specs); the physical file bindings come later.
  • Logical names in SSG parameters match @USE bindings. INPUT INB,500,10 tells the compiled COBOL to SELECT FILEIN ASSIGN TO DISC INB. The ECL then binds INB to a real file via @USE INB,I006VRM01ATT.
  • Record size and blocking factor are macro parameters. The same CFH-COPY template produces programs with completely different record structures in different job streams — no recompilation of the canonical source is needed.
  • *UTILIT is a Unisys file library qualifier, not a directory path. On the mainframe it identifies the library where the SSG source element resides.
  • @XQT .PROGNAME uses a dot prefix to reference the just-compiled program object that was placed in the TPF$ temporary namespace by @SSG,IA.
  • The compiled PROGRAM-ID may differ from the source element name. MONTANT_SIGNE (source element name) compiles a program whose PROGRAM-ID is simply MONTANT. The @XQT .MONTANT directive uses the PROGRAM-ID, not the element name.

Example 1 — MONTANT_SIGNE

Numeric amount field extractor  ·  PROGRAM-ID: MONTANT  ·  ✓ Trial 04 — Generated 2026-06-23

Purpose

MONTANT_SIGNE reads fixed-width sequential records, extracts N signed numeric (S9) amount fields at parameterised byte offsets, multiplies each by +1 (an identity transform — value preservation with sign normalisation), and writes the result to an output file. The compiled PROGRAM-ID is MONTANT.

In an AFBUS batch job, this utility normalises monetary amounts from one fixed-width file layout to another, where the number of amount fields, their byte positions, and their digit widths all vary per invocation via SSG macro parameters.

SSG Source — Full Annotated Listing

Source file: ASSURFED_UTILIT_MONTANT_SIGNE(P).TXT  (64 lines, Windows-1252 encoded)

               03 MONTANT[*I]  PIC S9([MONTANT,I,1,2]).

Example 2 — LECTIS_MULT

IS file multi-stream reader  ·  PROGRAM-ID: LECTIS  ·  ✓ Trial 05 — Generated + Trial 2026-06-25

Purpose

LECTIS_MULT reads records from one or more IS (Information Store) files — indexed sequential files backed by SQL in the WORKING_AFBUS_COBOL database. It optionally filters records by a CARTE key-list file, then outputs all matched records via DISPLAY UPON PRINTER. The compiled PROGRAM-ID is LECTIS.

IS files differ from flat files: they are SQL-backed, opened with OpenFile(), positioned with LocateRecordIndexedFile(), and iterated with ReadRandomAccessFileNextRecord(). Mock data for trials = SQL INSERT rows, not .DAT files.

ECL invocation pattern

ecl-template
@RUN LECTIS_MULT
@PARAM [COND,1]=0          // condition count (0 = no filtering)
@PARAM [ASCII]=1           // ASCII mode
@PARAM [LKEY]=1            // 1 key field per record
@PARAM [LKEY,1,1,1]=0      // key offset (byte)
@PARAM [LKEY,1,1,2]=8      // key width (bytes)
@PARAM [LKEY,1,1,3]=1      // alt key width
@PARAM [KEYS]=0            // 0 = sequential (no CARTE key list)
@PARAM [UN]=1              // 1 input file
@PARAM [INPUT,1,1,1]=FICHIN-1  // IS file name
@PARAM [INPUT,1,1,2]=120       // record size

SSG expansion concept

Three key branching constructs govern what code is generated:

  • [UN]/[DEUX]/[TROIS] — selects whether 1, 2, or 3 FICHIN streams are opened. Only the selected branches survive pre-processing.
  • [KEYS] — when 0: sequential read mode (all records). When >0: CARTE mode — a separate flat key-list file (CARTE-1) drives which records to read.
  • [COND,1] — when 0: the conditional filter block is a no-op; delete all 3 lines (see bare-IF fix below).

Bare-IF fix (new pattern — recorded here as Bug 17a)

When [COND,1,I,1] with COND,1=0 resolves to an empty string, CobolConverter generates:

7. Transformation Patterns

Each pattern was first validated on MONTANT_SIGNE and then applied to all other programs where the same SSG construct appears. Patterns are recorded in dependency order (T2 before T1 before T3).

Pattern: *DEFINE FILUN / *DEFINE FILDEU → static helper methods

First applied: MONTANT_SIGNE — 2026-06-25  |  Tier: T2

SSG Original

ssg-cobol
*DEFINE FILUN
*SET FILLUN  TO  [#1]-1
*END
*DEFINE FILDEU
*SET FILLDEU TO  [#1]-[#2]-[#3]+1
*END

C# Implementation

csharp
// Added to LocalDefinitions.cs

// SSG: *DEFINE FILUN → *SET FILLUN TO [#1]-1 → filler bytes before a signed field
private static int FilUn(int offset) => offset - 1;

// SSG: *DEFINE FILDEU → *SET FILLDEU TO [#1]-[#2]-[#3]+1 → trailing filler bytes
private static int FilDeu(int recordSize, int offset, int width) => recordSize - offset - width + 1;

Notes / Gotchas

These are pure arithmetic helpers with no side effects. They must be added before T1 because the T1 loop calls them inside the constructor. Parameter names map directly: [#1]=offset, [#2]=recordSize, [#3]=width for FILDEU. For MONTANT baseline (offset=2, width=9, recordSize=80): FilUn(2)=1, FilDeu(80,2,9)=70 — fixing the pre-Phase-15 hardcoded trailing filler of 1 (SIZE MISMATCH warning is now eliminated).

Applies to programs

All 16 SSG utility programs that use REDEFINES overlays over a working-storage record.

Pattern: *INCREMENT I FROM 1 BY 1 TO [MONTANT] … *LOOP → C# foreach

First applied: MONTANT_SIGNE — 2026-06-25  |  Tier: T1

SSG Original

ssg-cobol
*INCREMENT I FROM 1 BY 1 TO [MONTANT]
       01  WS-IN[*I] REDEFINES WS-IN.
*PROCESS FILUN [MONTANT,I,1,1]
               03 FILLER    PIC X([*FILLUN]).
               03 MONTANT[*I]  PIC S9([MONTANT,I,1,2]).
*PROCESS FILDEU [INPUT,1,1,2] [MONTANT,I,1,1] [MONTANT,I,1,2]
               03 FILLER    PIC X([*FILLDEU]).
*LOOP
…same pattern for WS-OUT…

       PROCEDURE DIVISION.
*INCREMENT I FROM 1 BY 1 TO [MONTANT]
           COMPUTE MONTANT[*I] OF WS-OUT[*I] = MONTANT[*I] OF WS-IN[*I] * +1
*LOOP

C# Implementation

csharp
// LocalDefinitions.cs — constructor (T1+T2 combined)
// Before: individual hardcoded AmtStructure/AmtVarNumericOS2200 fields
// After:  loop over (offset, width)[] fields array

private readonly List<AmtStructure> m_InStructures;
private readonly List<AmtStructure> m_OutStructures;
private readonly List<AmtVarNumericOS2200> m_InFields;
private readonly List<AmtVarNumericOS2200> m_OutFields;

public IReadOnlyList<AmtVarNumericOS2200> InFields { ... }
public IReadOnlyList<AmtVarNumericOS2200> OutFields { ... }

// Constructor loop:
foreach (var (offset, width) in fields) {
    var wsIn = new AmtStructure();
    wsIn.Redefines(m_Ws_In);
    wsIn.AddAlphaFiller(FilUn(offset));
    m_InFields.Add(new AmtVarNumericOS2200(width, true, wsIn));
    wsIn.AddAlphaFiller(FilDeu(recordSizeIn, offset, width));
    m_InStructures.Add(wsIn);

    var wsOut = new AmtStructure();
    wsOut.Redefines(m_Ws_Out);
    wsOut.AddAlphaFiller(FilUn(offset));
    m_OutFields.Add(new AmtVarNumericOS2200(width, true, wsOut));
    wsOut.AddAlphaFiller(FilDeu(recordSizeOut, offset, width));
    m_OutStructures.Add(wsOut);
}

// Montant.Core.cs — COMPUTE becomes loop
// Before: m_LocDef.Montant1_1.IntValue = m_LocDef.Montant1.IntValue * 1;
// After:
for (int i = 0; i < m_LocDef.InFields.Count; i++) {
    m_LocDef.OutFields[i].IntValue = m_LocDef.InFields[i].IntValue * 1;
}

Notes / Gotchas

The SSG loop generates N separate COBOL 01-level REDEFINES structures at compile time; the C# equivalent creates them dynamically at runtime. AllocStructure() must be called after all REDEFINES entries are built — not inside the loop. Each AmtStructure reference must be kept alive (stored in the list) to prevent GC collection of the shared memory buffer. IReadOnlyList prevents callers from accidentally modifying the field list while allowing indexed access in the COMPUTE loop.

All 16 SSG utility programs where *INCREMENT … *LOOP generates REDEFINES overlays.
