Step 12.6 — Verify PROGRAM-ID Matches Object Name in .LionSource

CobolConverterConsole.exe derives the object name from the SSG filename (e.g. ASSURFED_UTILIT_MONTANT_SIGNE(P)). After suffix-stripping, the stored name becomes ASSURFED_UTILIT_MONTANT_SIGNE, but the COBOL source body contains PROGRAM-ID. MONTANT. — a completely different identifier. The generator’s CobolApp.Sources.Find(objNameWm) indexes by PROGRAM-ID, so generation fails with Could not find source with name: MONTANT even after Step 12.5 cleans up the suffix.

Check before importing: open the .LionSource file in a text editor:

  • Find <OBJECT=…,COBOL PROGRAM> — the value between = and , is the stored object name
  • Find Name= in the <REVSET=…> block — same value
  • Find PROGRAM-ID. in the <DATA=Code> block — this is what the generator uses
  • All three should match after stripping any (P) / (F) / (S) suffix

Fix command (run before import):

powershell
$f = "C:\Amt\Migration\CobolConvert\output\my-source.LionSource"
Copy-Item $f "$f.bak" -Force
$content = [System.IO.File]::ReadAllText($f)
$content = $content -replace 'OldObjectName\(P\)', 'ACTUAL-PROGRAM-ID'
[System.IO.File]::WriteAllText($f, $content, [System.Text.Encoding]::ASCII)
⚠ Do NOT use Set-Content -Encoding UTF8 — PowerShell 5 writes a UTF-8 BOM. LionDev rejects the file with “Invalid source file”. Always use [System.IO.File]::WriteAllText(…, [System.Text.Encoding]::ASCII).

If already imported incorrectly: SQL-only renaming of REVSET/REVTREE is insufficient — REVDATA internal content becomes inconsistent. Delete the application from LionDev (right-click → Delete), fix the .LionSource file as above, then re-import via File → Import.
