How the conversion decides what to support: “real calls”, and what is left for Federale to prove

A skeleton contains more branches than Federale uses. Each generic program reproduces the branches that real calls use; for the others it either refuses them or keeps them and proves them with labelled test data only. This section defines the terms and lists the risks the Federale testers and business analysts have to close. Recorded 2026-11-18 (MT-069).

Definitions

TermMeaning
Real callan @SSG … *UTILIT.<skeleton> statement in a Federale production runstream, with the SGS cards it gives. Source: the index of the production runstreams (ssg4-source\RunsPrd-INDEX.csv, 1,080 runstreams) was scanned for *UTILIT.* calls: 170 contain one and form our source pack (01-RunsPrd, 371 @SSG calls); 3 more, outside the pack, call archive skeletons we do not have (ARCHITAB2/ARCHIFUSION). Every call's cards are exported to sgs-calls.csv and expanded with AMT's own SGS code.
“No real caller” for a branchnone of the real calls gives the card (or card value) that switches that branch on, so on OS 2200 it is never generated or run in production. It does not mean the skeleton lacks the code: the branch exists in the source and in the converted skeleton, but it is not used to specify the generic program, because no real call’s cards in production use it. Example: RECAP's 28 real calls (22 runstreams, all in the pack) all give ASCII; none gives ASCIIFD, CFH or Y2K.
Converted vs supportedtwo different things. The skeleton is converted mechanically and completely (SsgConverter): every branch, used or not, becomes PowerShell; RECAP's converted skeleton UTILIT_RECAP.ps1 still holds the ASCIIFD logic (12 tests). The generic program (RECAP_GN, hand-made) only supports the branches real calls use: it has no ASCIIFD code, and the hand-off refuses the card (L1). On the generic route the converted skeleton body never runs (the deployed skeleton calls the hand-off, then return), so an unused branch is converted but never executed.
Refused branchthe generic program's hand-off stops the job before the program runs (Abort, message naming the card and the limit, e.g. SSG-4 hand-off (RECAP): L3 Y2K not supported). A refusal is visible; it never gives a silent wrong result.
Kept, test data onlythe branch is in the generic program and proven only with labelled test cases (no real call): LECTIS (KEYS, Y2K, NOLIST; owner decision 261109), ARCHISEPARE / ARCHIFORMAT (no caller at all, MT-047).
Assumption pushed throughwhere the behaviour on OS 2200 is not known from the source or the Unisys manuals, the spec states a working assumption (A1, A2, …), why it is a reasonable bet, how a wrong one would show, and the team question that confirms it (Q1–Q12, plan 261116-db-ssg-programs-plan.md).
