SSG-4 — Convert SSG + ECL + COBOL on AMT's own tools, and run the result in AMT Control Center

From SSG skeleton + runstream cards to a C# program DLL (AMT's converters and LionDev), delivered into the VM's Federale AMT 177a, started as a Control Center job and proved by byte-comparing its output. Objective 1 of the Trial 4 epic.

Last updated: 2026-10-21  |  VM VMFEDPE08 (our copy of the client set-up)  |  Application AFBUS_2200COBOL_AMT (APPID 6)  |  Detail behind each step: PROCESS.md Steps 0–8 · Issues/ToDo: tracker §6/§7

Three layers, and which AMT tool converts each

A Federale report is three things on OS 2200. Trial 3 converted only the first (SSG) and its PowerShell ran to Fin because Call-ExternalProgram is a stub: there was never a program for Xqt to start. SSG-4 converts all three, on AMT's own converters, as a scripted pipeline.

LayerWhat it isActs atToolOur stepStatus
SSG skeletonTemplate (*SET, *DEFINE, *INCREMENT, SGS lookups) that generates COBOLgeneration timeSsgConverterConsole (our fixed SSG-3 build)C120 of 20
SGS cardsThe parameters after each @SSG call in a runstream, up to @EOF (INPUT INB,500,10, FIELDIN ...)input to generationnone in AMT (the converted runstream reads P$SGS\<run-id>)C2371 calls exported
COBOLThe business logic SSG produces from skeleton + cards (OPEN/READ/WRITE)run timeCobolConverterConsole → .LionSource → LionDev 177 → C#C3–C614 built, 13 delivered
ECL runstreamJob control: @ASG, @USE, @SSG, @XQTrun time (the job)EclConverterConsole → PowerShell on AmtPsEclLibC7experiment E1 only
Generation time vs run time. SSG variables decide what gets generated; they are not run-time variables of the program. So the skeleton is executed once per call with that call's cards (C3), and the COBOL it emits is what gets converted and run. Proof is an independent reference (from the cards and skeleton logic), never the converter's own earlier output. Search AMT first: reuse AMT library behaviour (e.g. its own SGS functions) before writing any emulation.

C2 · Export the SGS cards from the runstreams done

pwsh -NoProfile -File Conversion\Pipeline\Export-SgsCards.ps1 `
  -RunstreamDir E:\Repos\ssg4-source\01-RunsPrd -OutDir E:\Repos\ssg4-work\sgs-cards
  • Writes one card file per @SSG call (calls\<runstream>_<run-id>__L<line>.sgs), sgs-calls.csv (call → template → our program key) and sgs-warnings.csv. 371 calls, 359 on our converted programs. Re-runs are byte-identical.
  • Applies SSG's own card rules first, so AMT sees what SSG saw: continuations ( ;, ,;) joined, cut at an unquoted period, spaces after a comma removed, '' pairs dropped. Each change is listed as Changed; a quoted subfield with a space stays a Warning. Check: Test-SgsCardRules.ps1.
  • Template mapping: *UTILIT.<name>/ASCII in a runstream is the skeleton <name>_ASCII. ARCHIFORMAT, ARCHISEPARE and plain CFH-COPY have no call, so no real cards.

C3 · Expand skeleton + cards to COBOL

pwsh -NoProfile -File Conversion\Pipeline\Invoke-SsgExpansion.ps1 -Program CFH-COPY_ASCII `
  -CardFile E:\Repos\ssg4-work\sgs-cards\calls\ASSURFED_F999RUN_AFPH12__L427.sgs `
  -OutFile  E:\Repos\ssg4-work\expanded\CFH-COPY_ASCII.cob -RunInfo <run-id>,<account>,<project>
  • Runs the converted skeleton (C1) with AMT's own AddTo-SgsList, GetSgsValue, CompareTypeSafe, RemoveFrom-SgsList, Sort-SgsList, lifted unchanged from SsgConverter\Trials\RealRuntime\AmtPsEclLib.psm1; the Tier-1 mock only collects the output lines.

C4 · Convert the COBOL to a .LionSource

pwsh -NoProfile -File Conversion\Pipeline\Invoke-CobolConversion.ps1 `
  -CobolFile E:\Repos\ssg4-work\expanded\CFH-COPY_ASCII.cob -Name CFH-COPY_ASCII   # -BaseYear 1957 is the default
  • Writes <WorkDir>\out\<Name>.LionSource, the logs and the .xrf. Check Errors in the result before importing.
  • The object name in the .LionSource is the file name, and it must equal the PROGRAM-ID.
  • Exit code: 0 for warnings, 1 for errors; capture with redirection, not a pipe (a pipe gave a false -1).
  • Expected warnings on a clean run: customer settings not specified, XML comment elements in the macros file, REDEFINES SIZE MISMATCH.

C3+C4 · The release driver (normal route)

pwsh -NoProfile -File Conversion\Pipeline\Invoke-Ssg4Release.ps1 -Stage Prepare
  • For each program in -Programs (default: the 14 below) takes call -CallIndex (default 1) from sgs-calls.csv, expands it (C3) as ASSURFED-UTILIT-<KEY>, and converts all of them into one application AFBUS_2200COBOL.LionSource in E:\Repos\ssg4-work\release (via Build-AppLionSource.ps1).
  • Says whether the new .LionSource differs from the one imported last time (-Previous), and prints the LionDev steps with the exact file path. Stops on the first failure; changes nothing in Federale.
  • Progress lines are timestamped; full output goes to the work folder.

C8. Generic BABA — spec summary (done, 122 calls)

BABA reads one file and splits it into one or two outputs by a record key. One generic program, ASSURFED_UTILIT_BABA_GN, built once, runs every call from its cards, the same way as CFH-COPY. Full spec: Conversion\Pipeline\Generic\BABA\spec.md. Result 2026-10-20: done. One CC script job ran the 7 test cases as 7 runstream-style steps (job 624, Done in 24 s): 11 of 11 outputs byte-identical. On the way, the runtime misread a short-line parameter file for some sizes (T3-040); the hand-offs now write fixed-length lines (BABA 400, CFH-COPY 250), and the 4 CFH-COPY calls were re-run byte-identical.

C9. Generic FUSBA — spec summary (done, 36 calls)

FUSBA merges two key-sorted files: file 1 is the update file, file 2 the master. The output is a copy of the master that is split, cut down or updated by the update file. FUSBA2 is a variant. Both are run with @XQT TPF$.FUSBA, so one generic program, ASSURFED_UTILIT_FUSBA_GN, covers all 36 calls (32 FUSBA, 4 FUSBA2). Full spec: Conversion\Pipeline\Generic\FUSBA\spec.md. Result 2026-10-20: done. All 4 modes proven against real programs; in CC 12 of 12 outputs byte-identical (job 670), after two fixes: T3-041 (ours: the parameter file name stayed assigned between calls) and T3-040 (runtime reader rule; input maximum now 4001).

C12. LOADIS / UNLOADIS on CFH-COPY-GN (no new program, run in CC 2026-10-21)

LOADIS copies a sequential file into an indexed one (ACCESS SEQUENTIAL, one key from KEYIS offset,length,rest); UNLOADIS copies it back. Both have the same INPUT/OUTPUT cards as CFH-COPY, so the hand-off (Conversion\Pipeline\Generic\LOADIS\gen\LoadisParm.ps1, Invoke-LoadisHandoff -Mode LOADIS|UNLOADIS, in all four skeletons ASCII and MULTI) maps Xqt TPF$.LOADIS / TPF$.UNLOADIS to CFH_COPY_GN as a whole-record copy. For LOADIS it also reads the input, checks the key order and writes the .Index before the Xqt.

FactEvidence
An AMT indexed file is the data file (records + CRLF) plus <file>.DAT.Index: =W*2, Int32 6, Int64 data length, data path (255 bytes), 01 01, Int32 key count, Int32 key offset (0x115), Int32 key length (0x119), Int32 0, Al, Int32 entries, then per record in key order the key and an Int64 record number (0-based)rebuilt byte for byte from the data file for both CC-written indexes
The static UNLOADIS reads the data file in stored order and ignores the .Indexmock: reversed data with a valid index came out reversed; a header with another key gave no error (check\Test-OptionD2.ps1)
Job files are file-controller paths (\EXTRACTS\... from Get-AssignedFile); read and write them through $global:AmtFile, not [IO.File]first runs: relative path, and the file is locked by the job's own Asg
An assigned output lives in \EXTRACTS\TPF$<run>\<qualifier>\ until Free, which moves only the data file of a file the program did not open as indexed; the hand-off writes the index to both places. The runtime writes that TPF$ path, upper case, in the headerjob log, job 807

Gotchas

  • Restart, not Start: -Action Start skips running services, so new DLLs are not picked up.
  • Basepaths set is shared by FEDERALE_APP and AFBUS_2200COBOL_AMT; never edit it for this work.
  • Never Reo all, never reorganize System or FEDERALE_APP.
  • 177 vs 177a: the Reorganize tool needs the 177 application DLLs; the runtime needs the 177a programs.
  • AMT adds .DAT to logical file names: INASC is read from INASC.DAT.
  • Indexed files come as a pair (X.DAT + X.DAT.Index); copy and clean both.
  • First error is in the main trace: check FederaleBatchController.Log before the per-job log (T3-010).
  • One job at a time: jobs share the Extracts folder; a parallel run could read another's output.
  • FederaleTransactionServer stops after start (T3-014): FEDERALE_APP only, ignore here.
