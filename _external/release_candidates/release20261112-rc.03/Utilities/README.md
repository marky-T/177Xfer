# Utilities — generic programs for the converted SSG utilities

Release `release20261112-rc.03` · application **BSP** · 10 programs for 11 utilities (16 SSG skeletons).

On OS 2200, batch runstreams called **SSG skeletons** (utilities such as CFH-COPY, BABA or FUSBA). For each call, SSG read
the call's parameter cards and generated and compiled a new COBOL program. In AMT each utility is **one generic program,
built once**, that reads the call's cards at run time from a parameter file written by a hand-off in the converted skeleton.

Specification, flow diagrams and the list of calling runstreams: [PROGRAM-SUMMARY.md](PROGRAM-SUMMARY.md). What is in this
release and what is known to be open: [RELEASE-NOTES.md](RELEASE-NOTES.md). Installation: [INSTALL.md](INSTALL.md).

## How a utility runs

A program is never started on its own. A **calling parent**, a converted runstream (`Scripts\ASSURFED_F999\...`), reaches the step:

1. `Invoke-Ssg -Skeleton "../../ASSURFED_UTILIT/UTILIT_<X>" -SgsFile ...` runs the skeleton with the call's cards.
2. The hand-off at the top of the skeleton (`<X>Parm.inc` + `GnHandoff.inc`) writes the parameter file, maps the call's file
   names to the program's fixed names, sets the output record sizes, checks the cards (stopping the job if they are invalid), and returns.
3. The step's `Xqt` is mapped by `CloneReports` in `Scripts\Settings\AmtSettings.xml` to the generic program, which runs as a
   child job **named after the Xqt**, *Started by* the runstream.

## Maintenance

- Change a call: change its cards in the runstream; nothing is rebuilt.
- Program logic: edit the C# in `BSP_AMT\Development\Programs\<Project>` (generated by LionDev 177, application BSP, made relative like the
  other programs). The COBOL in `Reference\Cobol` is for reading; it is not maintained.
- Parameter file layout and checks: the `.inc` files in `Scripts\ASSURFED_UTILIT`, edited in place. `GnHandoff.inc` is the common part.
- Keep every variable-length input record maximum at 4001 bytes (`AmtVarAlpha(4001, ...)` in `Fd_*.cs`).
- Re-test after a change: compare outputs byte for byte with known-good results (see RELEASE-NOTES, Control Center proof).
